# Terms of use, source by source

May a publicly distributed copy of dataseek query each source the way its adapter does? Every row below was checked on 2026-10-06 against the provider's own terms, API pages and `robots.txt`, with the live endpoint, and judged for a public release: thousands of installs sending the adapter's request with one shared User-Agent and contact address. A row rests on a quoted sentence; where the terms are silent the verdict says so, because silence in the terms is never permission.

Verdicts: **keep** (the provider documents or invites this use), **keep with conditions** (the use is allowed or not forbidden, with something to honour or confirm), **opt-in only** (asked only when named, [ADR 0013](../adr/0013-opt-in-sources.md)), **drop** (none). Where the table says `unclear`, no sentence in the terms speaks to a third-party client querying this endpoint.

## What the terms ask the tool to show

The README's Data sources section carries all of these. `dataseek sources` also prints the FRED and Census notices under its table, because their terms ask for the notice in the application itself.

- FRED: the notice "This product uses the FRED(R) API but is not endorsed or certified by the Federal Reserve Bank of St. Louis." and a link to the terms in any application that uses the API.
- Census Bureau: "This product uses the Census Bureau Data API but is not endorsed or certified by the Census Bureau."
- NCBI: the E-utilities disclaimer and copyright notice must be evident to users; the tool and e-mail pair must be registered with NCBI.
- WHO: citation in the form "World Health Organization {YEAR} data.who.int, {ITEM_NAME} [{ITEM_TYPE}]. {URL} (Accessed on {ACCESS DATE})".
- OpenAIRE, GBIF, Eurostat, ECB, Bundesbank, OECD, IMF, Data.gov, Materials Project: acknowledgement of the source when the data is reused; dataseek prints each result's publisher and link.
